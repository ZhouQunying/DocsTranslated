# Channels

**总结：** 各 channel 独立配置——`channels.*` 下的 key，覆盖 DM/群组访问控制、多账户、mention gating，以及 Slack/Discord/Telegram/WhatsApp/Matrix/iMessage 等每个 channel 的专属参数。

> **类比：Terraform 多 provider 块 + AWS Security Group。** Terraform 每个 provider（aws/gcp/azure）有独立认证和资源块互不干扰，Security Group 按 inbound/outbound 规则控制访问。OpenClaw channels 类似——每个 channel（WhatsApp/Telegram/Discord/Slack/Matrix/iMessage/Signal/Google Chat/Mattermost/Teams/IRC/Feishu 等）有独立配置块、独立认证（token/session/cookie），统一 DM policy（`pairing`/`allowlist`/`open`/`disabled`）和 group policy（`allowlist`/`open`/`disabled`），mention gating 控制群组响应行为，multi-account 支持同 channel 多 bot 身份。
>
> **架构要点：** 统一访问控制：DM policy（`pairing` 配对/`allowlist` 白名单/`open` 开放/`disabled` 禁用）、group policy（`allowlist`/`open`/`disabled`）；channel model override：`channels.modelByChannel` 按 channel ID 指定模型（`provider/model` 或 alias）；channel defaults：共享 group policy/context 可见性/heartbeat 行为；WhatsApp：基于 Baileys Web，linked session 存在时自动启动；Telegram：bot token、multi-account、retry policy、streaming mode、custom command、topic-level override；Discord：token auth、guild/channel routing、streaming、voice、thread binding、exec approval、UI component；Slack：Socket Mode + HTTP Mode、slash command、streaming、exec approval、per-channel/thread session 隔离；Google Chat：service account auth、DM/group policy、space-level 访问控制；iMessage：`imsg rpc` stdio、SSH wrapper 远程 Mac、attachment 处理、private API action；Matrix：plugin-backed、token/password auth、proxy、multi-account、encryption、exec approval；Signal：account binding、DM policy、reaction notification；mention gating：群组默认要求 mention（metadata mention + text pattern）、visible reply mode；command：native command、text slash command、bash access、config write、owner-only 授权；multi-account：所有 channel 支持多账户，`accountId` 省略时用 `default`。
