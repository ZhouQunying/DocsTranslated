# Exposure runbook

## 架构精读

> 跳过不影响阅读翻译正文。

### Exposure runbook

**问题**: 把 Gateway 暴露到网络前,如何系统性检查安全配置?

**方案**: 4 项检查清单:
1. **谁能访问?** (Who can reach?)
2. **怎么认证?** (How authenticated?)
3. **触发哪些 agent?** (Which agents triggered?)
4. **能用哪些工具?** (Which tools available?)

**洞察**: 暴露 Gateway = 把控制权交给外部用户。不检查 = 可能安全事故。

**权衡**: 
- ✓ 系统性: 不遗漏关键安全点
- ✗ 繁琐: 每次暴露前都要检查

**模式**: 飞行员飞行前检查清单——起飞前逐项检查,不检查 = 可能坠机。

### 谁能访问?(网络可达性)

**问题**: Gateway 暴露到什么范围?

**方案**: 三级:
- **本地**: 只有 `localhost` (最安全)
- **局域网**: 同一网络内设备 (中等安全)
- **公网**: 任何有 IP 的人 (最不安全)

**洞察**: 网络可达性 = 谁能访问 = 需要什么级别的认证。

**权衡**:
- ✓ 本地: 不需要复杂认证
- ✗ 公网: 需要强认证 (OAuth + MFA)

**模式**: WiFi 可见性——隐藏 SSID (本地)、广播 SSID (局域网)、放在街上 (公网)。

### 怎么认证?(身份验证)

**问题**: Gateway 用什么认证方式?

**方案**: 四级:
- **无认证**: 任何人访问 (危险)
- **API 密钥**: 知道密钥的人访问 (中等)
- **OAuth**: OAuth 提供者认证 (高)
- **受信任代理**: 反向代理认证 (如 nginx + X-User-*)

**洞察**: 认证 = 谁能控制 agent + 能做什么。

**权衡**:
- ✓ 无认证: 简单
- ✗ 危险: 任何人都能控制 agent

**模式**: 门锁——无锁 (任何人进)、普通锁 (钥匙进)、智能锁 (指纹/密码进)。

### 触发哪些 agent?(agent 路由)

**问题**: 用户消息能触发哪些 agent?

**方案**: 三级:
- **所有 agent**: 危险 (如 coding agent 能执行 shell)
- **特定 agent**: 安全 (如只触发 support agent)
- **无 agent**: 只返回错误

**洞察**: 不同 agent 有不同权限,路由规则 = 限制用户能触发哪些 agent。

**权衡**:
- ✓ 所有 agent: 灵活
- ✗ 危险: 用户可能触发危险 agent

**模式**: 餐厅菜单——限制了"顾客能点什么"。

### 能用哪些工具?(工具权限)

**问题**: Agent 能用哪些工具?

**方案**: 三级:
- **所有工具**: 危险 (执行、文件写入、HTTP 请求)
- **特定工具**: 安全 (只读工具)
- **无工具**: 只能对话

**洞察**: 工具 = agent 的"手",工具权限 = 限制 agent 能做什么。

**权衡**:
- ✓ 所有工具: 功能强大
- ✗ 危险: 用户可能让 agent 执行恶意操作

**模式**: SELinux 策略——限制进程能做什么。
