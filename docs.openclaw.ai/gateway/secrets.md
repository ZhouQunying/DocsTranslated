# Secrets Management

**总结：** 使用 additive SecretRef 让管理员把敏感凭证从明文配置文件中移出——env/file/exec 三种 source。

> **类比：HashiCorp Vault + K8s Secret。** Vault 把敏感数据集中管理（动态 secret、加密、审计），K8s Secret 把密码/token 从 Pod spec 中抽离。OpenClaw SecretRef 类似——把 API key/token 从 `openclaw.json` 明文中抽离，指向 env var/file path/exec command（如 1Password CLI、Vault CLI），运行时 eager resolve（启动时解析到内存快照），atomic swap（热重载时原子替换），fast failure（无效引用阻止启动）。
>
> **架构要点：** Goals + runtime model：eager memory resolution（启动时解析所有 SecretRef 到内存）、atomic swap（更新时原子替换，无中间状态）、fast failure（无效引用阻止启动）；agent-access boundary：SecretRef 防止 config 持久化明文，但不隔离进程读取磁盘文件的能力；active-surface filtering：仅 enabled surface 校验 SecretRef（dormant surface 发非致命诊断 code）；gateway auth surface diagnostics：启动/更新时 log gateway auth ref 的 active/dormant 状态；onboarding preflight：初始设置交互校验 env/provider ref；SecretRef contract：标准 object shape（env/file/exec source）+ 校验规则；provider config：env（`${VAR_NAME}`）、file（路径读取）、exec（命令执行，如 `op read`、`vault kv get`）；file-backed API key：credential 字段直接用 file ref；exec integration：1Password/Bitwarden/Vault/password-store/sops 示例；MCP server env var：隐藏 MCP plugin API token；sandbox SSH auth：SSH identity/certificate/known_hosts 支持 ref；supported credential surface：文档列出哪些 credential 支持 ref（哪些故意排除）；precedence：ref > plain text，redaction sentinel，audit warning；activation trigger：startup/hot-reload/manual command；degraded + recovered signal：reload 失败时 log degraded，恢复后 log recovered；command-path resolution：strict path fast-fail，read-only path degrade gracefully；audit workflow：CLI check → apply → re-verify；one-way safety：不生成包含旧明文 credential 的 recovery archive；legacy auth compat：runtime 依赖内存快照，scrub 旧静态 key。
