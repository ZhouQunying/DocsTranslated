# Doctor

## 架构精读

> 跳过不影响阅读翻译正文。

### `openclaw doctor`

**问题**: OpenClaw 状态复杂 (配置文件、数据库、auth 凭证、session 历史),手动检查太麻烦?

**方案**: `openclaw doctor` 诊断 + 修复 + 迁移:
```bash
openclaw doctor
```

检查:
- 配置文件 schema (拼写错误、字段缺失)
- 状态文件损坏 (session 数据库、auth 数据库)
- 版本兼容性 (老版本格式需要迁移)
- 权限问题 (文件权限不对)

修复:
- 自动修复简单问题
- 提供修复建议
- 迁移老版本配置

**洞察**: 自动扫描,列出所有问题,提供修复方案。

**权衡**:
- ✓ 自动化: 不需要手动检查
- ✓ 完整: 检查所有状态

**模式**: `brew doctor`——检查系统状态,列出问题,提供修复建议。

### `--yes`

**问题**: CI/CD 或自动化脚本里,不能交互式确认?

**方案**: `--yes` 自动确认所有修复操作:
```bash
openclaw doctor --yes
```

**洞察**: 自动执行所有修复,不中断流程。

**权衡**:
- ✓ 自动化: 不需要手动确认
- ✗ 风险: 如果修复建议有问题,会自动执行

**场景**: CI/CD 跑测试 (可信环境),不适合生产环境。

### `--fix`

**问题**: 只想应用推荐的修复,不想执行危险操作 (如删除文件)?

**方案**: `--fix` 应用推荐的修复:
```bash
openclaw doctor --fix
```

**洞察**: 比 `--yes` 更安全,不执行危险操作。

**权衡**:
- ✓ 安全: 不执行危险操作
- ✓ 推荐: 日常使用

**跟 `--yes` 的区别**:
- `--yes`: 确认所有操作 (包括重启、删除文件)
- `--fix`: 只应用推荐修复,不执行危险操作

### `--lint`

**问题**: 想先看看有什么问题,再决定是否修复?

**方案**: `--lint` 只检查,不修复:
```bash
openclaw doctor --lint
```

**洞察**: "只读"模式,不修改任何文件。

**权衡**:
- ✓ 安全: 不修改文件
- ✓ 预览: 先看问题再决定修复

**模式**: ESLint——检查代码问题,列出错误,不自动修复 (除非用 `--fix`)。

### `--fix --force`

**问题**: 配置文件严重损坏,普通 `--fix` 无法修复?

**方案**: `--fix --force` 强制修复:
```bash
openclaw doctor --fix --force
```

**洞察**: 做更激进的修复 (如删除损坏的数据库、重建配置文件)。

**权衡**:
- ✓ 强大: 可以修复严重损坏
- ✗ 风险: 可能丢失数据

**场景**: 普通 `--fix` 失败时使用。

### `--non-interactive`

**问题**: CI/CD 或自动化脚本里,不能交互式回答?

**方案**: `--non-interactive` 不显示交互式提示:
```bash
openclaw doctor --non-interactive
```

**洞察**: 跳过所有交互式提示,使用默认值。

**权衡**:
- ✓ 自动化: 不需要手动回答
- ✓ 安全: 默认值通常是安全的

**跟 `--yes` 的区别**:
- `--yes`: 自动确认所有操作
- `--non-interactive`: 跳过提示,但不一定执行操作 (如"是否重启"默认值是"否",就不重启)

### Doctor 的输出

**问题**: "有 X 个问题" 不够,用户需要知道"怎么修复"?

**方案**: 输出可操作的修复步骤:
```
[WARNING] config.auth.apiKey is plaintext
  Fix: Run `openclaw secrets apply` to migrate to SecretRef

[ERROR] sessions.db is corrupted
  Fix: Delete ~/.openclaw/sessions.db and restart Gateway
```

**洞察**: 问题 + 修复建议,用户可以直接复制粘贴执行。

**权衡**:
- ✓ 可操作: 提供具体修复命令
- ✓ 清晰: 问题和修复对应

**模式**: `npm audit`——不只说"有漏洞",还说"运行 `npm audit fix` 来修复"。
